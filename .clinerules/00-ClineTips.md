# Cline Tips

Clineで作業を行うときの所作

## コマンドは30秒でエラーになる

-- 長いコマンドを実行するとき、sleepで遅延させるがsleepの時間は30秒未満にすること。

## 6回同じコマンドを実行するとエラーになる

-- 同じコマンドを6回実行する前にpwd等の影響がないコマンドを空実行するか、clineが成功と判定するコマンドを実行すること。

## シェルコマンドが実行不能になることがある (2026-10-20 実測)

-- 長時間セッション (headless Chrome + CDP 検証の反復) でシェルコマンドが一切実行できなくなる不具合が
   発生し、セッションを引き継いで復旧した。コマンド内容が原因ではないので、再発したら同じコマンドを
   新しいセッションで実行するのが最速。引き継ぎ文には「完了済みの検証 / 残タスク / 用意してある
   スクリプトのパス / 既知の落とし穴」を詰めると、新セッションで文脈再取得のコマンド実行を
   スキップできる (この不具合の回避にもなる)。

## Cline が作った検証スクリプトの FAIL も疑う

-- 実測値が期待どおりなのに FAIL になるのは判定式のバグが多い。JS 側で join した値は真偽値が
   小文字 "false"、数値は 67.0 → "67" になる点に注意。判定がクラッシュして本題の比較が
   走っていない場合もあるので、レポートの最終行 (ALL PASS / DONE) まで確認する。

## 常駐プロセスを落とすとき

-- `pkill -f '<パターン>'` は自分のコマンドラインにもマッチして自爆する。ポート指定で止めるなら
   `fuser -k <port>/tcp` を使う。長時間スクリプトは nohup で裏に回し、ログを見るなら `python -u`
   (リダイレクト時はブロックバッファで途中出力が見えない)。
